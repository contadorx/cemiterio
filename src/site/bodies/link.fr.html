Un lien prêt pour votre système de test

Composez ici une adresse qui ouvre {{marca}} avec le cas de test, le ticket et le système déjà remplis. Collez-la dans Zephyr, dans Jira, dans Xray, dans TestRail, dans Azure DevOps, dans qTest — ou dans un tableur.
Ce n’est pas une intégration et cela n’a besoin de la DSI de personne. C’est un lien. N’importe quel outil qui affiche un lien fait l’affaire, et c’est voulu : une vraie intégration dépend d’une API, d’une autorisation et d’un projet approuvé ; un lien fonctionne lundi.

Offre Team — activer par le lien lui-même (optionnel)

Collez ici la clé que vous avez reçue. Le lien se met alors à activer l’offre Team dans le navigateur de qui l’ouvre, et il amène déjà le nom du client dans le document — personne dans l’équipe n’a de clé à coller. La clé est lue ici, dans votre navigateur, et n’est envoyée nulle part.

Où ne pas coller ce lien : dans un ticket que n’importe qui dans l’entreprise peut ouvrir, dans un canal public, dans un document partagé avec le client. Qui a le lien a l’offre. Pour ces endroits-là, utilisez le lien sans la clé — il continue de remplir le cas et le ticket.

Le logo ne voyage pas dans le lien : une adresse ne transporte pas de fichier, et aller chercher une image sur internet pour la mettre dans le document casserait la promesse que rien n’entre et rien ne sort. Il se choisit une fois, dans l’outil.

Comment cela entre dans Zephyr

Deux façons, et les deux prennent moins d’une minute par cas :

  1. Dans le cas de test lui-même. Collez le lien dans une étape du test script ou dans la description — quelque chose comme « enregistrez la preuve ici ». La personne qui exécute clique, enregistre, génère le PDF et le joint à l’exécution. Le nom du fichier sort déjà avec le cas et le ticket dedans, donc il s’explique tout seul dans la liste des pièces jointes.
  2. Dans une automatisation. Si la création du cycle de test est automatisée, composez le lien avec les champs du cas lui-même. Le format est celui-ci, et il ne change pas : {{site}}/app?modelo=evidencia&caso=CT-014&chamado=NAT-1234&sistema=S4P/100

Cela vaut pareil pour Xray, pareil pour Jira seul, et pareil pour un tableur partagé. C’est l’avantage de ne pas être une intégration.

Ce que le lien fait et ce qu’il ne fait pas

Il fait : il ouvre l’outil avec les champs remplis, dans la bonne langue et le bon modèle de sortie. La personne qui exécute ne saisit rien et ne choisit rien — et c’est pour cela que la preuve de toute l’équipe sort au même standard, sans que personne soit formé.

Il ne fait pas : il ne rattache rien en retour dans votre système, parce que cela demanderait une API et une autorisation. Le chemin du retour reste de glisser le fichier — trois secondes, et cela marche dans n’importe quel outil, y compris ceux que votre entreprise ne laisse pas intégrer.

Une précaution. Ce qui part dans l’adresse reste dans l’historique du navigateur de qui l’ouvre et dans les journaux de qui sert la page. Un nom de système et un numéro de ticket, aucun souci ; un nom de personne, un e-mail ou n’importe quelle donnée personnelle, mieux vaut laisser vide et saisir à l’écran.

Combien cela coûte

Rien. Cela fait partie de l’offre gratuite et cela va le rester — c’est ce qui fait entrer l’outil dans le processus que votre équipe a déjà, et un outil qui ne marche que tout seul ne sert à aucune équipe. Ce qui est payant est sur la page des tarifs : le logo du client dans le document et le lexique métier partagé.
